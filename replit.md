# Maven AI — Marketing Website + Diagnostic Suite

## Overview
This project delivers a world-class marketing website for Maven AI, an AI advisory and engineering services firm. It's built as a React + Vite single-page application. A key enhancement is the integration of the Maven AI Diagnostic Assessment Suite, offering four free, bilingual (EN/AR) diagnostic wizards (ARI, MVI, DAFI, UVR). This suite is supported by an Express API, uses Postgres for persistence, and generates AI-powered executive memos and branded PDF reports. The website aims to showcase Maven AI's expertise, services, and diagnostic capabilities, with a strong focus on a premium user experience and robust functionality.

## System Architecture
The project is built on a modern web stack: React, Vite, TypeScript, Tailwind CSS v4, Framer Motion, and Wouter for routing, managed within a pnpm monorepo. The design emphasizes a McKinsey/Accenture-quality aesthetic, utilizing a consistent brand identity with a navy (`#0E2841`), teal (`#156082`), and amber (`#F5A623`) color scheme, and Plus Jakarta Sans for typography.

**Key Features:**
- **UI/UX:** Responsive design with mobile-first considerations, animated sections using Framer Motion, and a sophisticated visual language. The site includes a floating amber FAB for the chat widget, which also supports full-screen mode on mobile.
- **Content Management:** All static content (founders, services, insights, industries) is centrally managed within `src/data/content.ts` and `lib/maven-content`.
- **Navigation & Routing:** Comprehensive routing handles main pages, service details, insight articles, industry profiles, a dynamic marketplace for demo tools, and dedicated routes for diagnostic assessments and multi-variant demos (e.g., `/demo/:slug/:variant`).
- **Marketplace:** Features a filterable catalog of demo tools with detailed pages showcasing screens, data models, and multi-demo variants. Includes flagship demos like Value Realization and fully bilingual (TR/EN) demos for Arçelik Pricing Intelligence with both Business Dashboard and Dealer Portal variants. These variants include complex UIs such as KPI summaries, heatmaps, radar charts, campaign builders, pricing simulators, and Gantt calendars, all with AI chat integrations and bilingual intent patterns. The Arçelik demo includes an agentic pricing intelligence layer (`arcelik-agent.ts`, `AgentDecisionsView.tsx`) with reasoning traces, approve/reject/modify workflows, decision history, playbooks, and cross-view agent integrations. Product selection follows a category-first pattern: SimulatorView uses `<optgroup>` elements grouped by CATEGORY_LABELS, CampaignBuilder offers collapsible product-level targeting within selected categories, and PriceListView/DashboardView already use category tabs/filters.
- **Arçelik Demo Data Architecture:** All pricing data is stored in PostgreSQL (12 Drizzle schema tables in `lib/db/src/schema/arcelik.ts`: arcelik_products, arcelik_competitor_prices, arcelik_data_sources, arcelik_cities, arcelik_dealers, arcelik_campaigns, arcelik_kpi_benchmarks, arcelik_promotional_calendar, arcelik_price_history, arcelik_scrape_logs, arcelik_marketplace_prices, arcelik_product_equivalences) with `dataProvenance` ("manual-verified"|"auto-scraped") and `scrapedAt` columns on products and competitor_prices tables. Baseline pricing data lives in `scripts/src/arcelik-baseline.json` with provenance metadata (sources, verification date). Data is seeded via `scripts/src/seed-arcelik.ts` which loads baseline from JSON and runs scraper modules for arcelik.com.tr, beko.com.tr, vestel.com.tr, bosch-home.com.tr, samsung.com/tr. Scraping is default behavior; enforcement gate fails seed if scrape coverage < threshold (default 10%) unless `--force` is used. Flags: `--no-scrape` (baseline only), `--force` (bypass gate), `--min-coverage=N` (adjust threshold), `--dry-run`. Unmatched SKUs are logged during scraping. **Automatic price updates:** A node-cron scheduler in the API server (`artifacts/api-server/src/lib/scheduler.ts`) runs scrapers daily at 03:00 UTC (configurable via `PRICE_SCRAPE_CRON` env var). The scraper service (`artifacts/api-server/src/lib/scraper.ts`) re-scrapes all 5 competitor websites, matches prices to existing DB records, records price history (timestamped records in `arcelik_price_history`), and logs each run in `arcelik_scrape_logs`. Manual scrapes can be triggered via `POST /api/arcelik/scrape`. Price history tracks both product and competitor price changes with previous price, change percentage, and source URL. The `usePriceHistory` hook (`artifacts/maven-ai/src/hooks/usePriceHistory.ts`) provides React Query-based access to `/api/arcelik/price-history` and `/api/arcelik/price-history/summary` with 60s stale time and 5min polling. DashboardView uses real price history for sparkline trend charts in the product comparison table (falling back to synthetic data when history is empty), and enriches the Competitor Price Index KPI card with summary-derived trend data and data point counts. CompetitorRadarView builds dynamic timeline events from significant price changes (|change| > 2%) and renders a LineChart showing average price trends per brand over time (conditionally shown only when data exists). Both views gracefully fall back to static/synthetic data when no price history records are available. API endpoints at `/api/arcelik/*` (11 routes in `artifacts/api-server/src/routes/arcelik.ts`) serve data to the frontend, including `GET /price-history`, `GET /price-history/summary`, `GET /scrape-status`, and `POST /scrape`. The dashboard shows a "last updated" status bar with scheduler info, update timestamps, and tracking counts via the `useScrapeStatus` hook. React components use `useArcelikData()` hook (React Query + Context in `artifacts/maven-ai/src/hooks/useArcelikData.tsx`) for data access; non-React files (arcelik-agent.ts, chatIntents.ts, dealerChatIntents.ts) use `getArcelikDataSnapshot()`. The `ArcelikDataProvider` wraps demo routes in Demo.tsx with error state UI and retry button. The database contains 105 products across 7 categories, 82 competitor prices, 20 cities, 15 dealers, 8 campaigns, 8 KPI benchmarks, 16 promotional calendar entries, and 11 data sources. `arcelik-seed.ts` (in `artifacts/maven-ai/src/data/`) now contains only TypeScript interfaces, type definitions, label constants (CATEGORY_LABELS, COMPETITOR_BRANDS, PRICE_TIER_LABELS), and bilingual helper functions — no data arrays. The Turkey map (`TurkeyMap.tsx`) renders geographically accurate province boundaries sourced from open-source GeoJSON data (`cihadturhan/tr-geojson`), with 7 color-coded regions and all 81 province outlines projected via Mercator into a 650x185 SVG viewBox. City positions are computed as polygon centroids. The generation script is at `scripts/generate-turkey-map.mjs`.
- **Arçelik Demo i18n:** Full TR/EN internationalization via `DemoLangContext.tsx` (React context with sessionStorage persistence) and `demo-i18n.ts` (350+ keys across 14 named sections). TR/EN pill toggle in both dashboard headers. All 12+ view files use the pattern `const { lang } = useDemoLang(); const t = section[lang];`. Chat intents (`chatIntents.ts`, `dealerChatIntents.ts`) accept `lang` parameter for bilingual pattern matching and responses. Seed data uses bilingual helper functions from `arcelik-seed.ts`: `getProductName(p, lang)` for regex-based product name translation (with 40+ PRODUCT_NAME_SUBS patterns), `getCampaignField(c, field, lang)` for all 11 campaign text fields, `getCitySeasonalPattern(city, lang)` for city seasonal descriptions, `getCalendarEntryName(entry, lang)` for promotional calendar entries, `getKpiLabel(kpi, lang)` for KPI benchmarks, `getCategoryLabel(cat, lang)` for category names, and `getSubcategoryLabel(sub, lang)` for 34 subcategory labels. Currency/number formatting always uses `tr-TR` locale regardless of language. City names are proper nouns and remain unchanged across languages.
- **Diagnostic Suite:** Comprises a shared TypeScript library for the scoring engine, i18n, and framework definitions. The UI includes a wizard engine, results screens with gauges, radar charts, heatmaps, and a portfolio view, plus React-PDF for branded reports, supporting both English and Arabic with an RTL toggle.
- **AI Chat Assistant:** A site-wide assistant integrates with both server-side (Anthropic/OpenAI) and client-side logic. It leverages a shared `knowledgeBase` from `lib/maven-content`, uses an OpenAPI-defined `POST /chat` endpoint for SSE, implements a strict allow-list for internal links, and provides a user-friendly interface with rate limiting, streaming responses, and session persistence.

## Scraper Architecture
The price scraping system lives in two parallel codebases that must be kept in sync:
- `artifacts/api-server/src/lib/scraper.ts` — runtime scraper used by the API server's daily cron job and manual POST /api/arcelik/scrape endpoint
- `scripts/src/seed-arcelik.ts` — seed-time scraper used during initial database population

**Cheerio-based scrapers:**
- **Vestel** (63 products): URLs `/buzdolabi`, `/camasir-makinesi` (singular!), `/bulasik-makineleri` (plural!). Selectors: `.product-list-item-wrap`, `.product-title`, `.product-price-helper`. Model codes from `data-product-id` attribute or regex extraction from product name.
- **Bosch** (36 products): URL pattern `/tr/category/{cat}` with categories `buzdolaplari-derin-dondurucular`, `camasir-makineleri`, `bulasik-makineleri`. Uses stable `data-testid` attributes: `product-teaser-container-for-*`, `product-code`, `product-teaser-header-headline`, `price-main-price`. First product per category has CSS garbage in headline — filtered with `.includes("{")` check.
- **Samsung** (38 products): URL pattern `/tr/{cat}/` with geo cookies `country_codes=tr; country_region=TR`. Parses JSON-LD `ItemList` structured data. No SKU field — model codes extracted from URL slugs via regex `[-]([a-z]{2}\d{2,}[a-z0-9]*)\/?$`.

**Playwright-based scrapers (Arçelik 79 products, Beko 60 products):**
- Both sites run on the **Hybris e-commerce platform**, sharing the same DOM structure. The `scrapeWithPlaywright()` helper extracts from `article.prd.product-item` containers, parsing the `data-gtm-impression` JSON attribute for clean `name`, `id`, and `price` fields.
- Fallback chain: `data-product-code` / `data-product-name` attributes + `span.prc.prc-last` text → generic `[data-product-id]` selectors.
- Headless Chromium is launched with `--disable-blink-features=AutomationControlled` plus a realistic Chrome user-agent and `Accept-Language: tr-TR` headers. This is enough to pass Akamai for both sites — no stealth plugin or residential proxy needed.

**Model matching:** Baseline data in `arcelik-baseline.json` has model codes from Vestel (63 products), Bosch (36), Samsung (38). The scraper uses `buildEnhancedMap()` which indexes scraped products by both modelCode and name-extracted tokens for fuzzy matching (45/82 competitors matched, 8/105 own-products matched). Arçelik own-product match rate is low because the scraped Arçelik IDs are 10-digit catalog numbers (e.g. `7286520155`) while baseline uses short codes (e.g. `5088 NFK`); refreshing baseline modelCodes against scraped names is a future improvement. LG and Electrolux remain unmatched (19 entries) due to no scraper coverage.

**N11 marketplace + cross-brand equivalences (May 2026):** A new Playwright-based scraper (`scrapeN11()` in `scraper.ts`) walks 6 N11 categories (`buzdolabi`, `camasir-makinesi`, `bulasik-makinesi`, `firin`, `klima`, `kurutma-makinesi`) with `?pg=N` pagination, parsing `a.product-item[data-prod-id]` cards and the Vue-rendered `.basket-price .price-currency` price element. Each scrape returns ~260 multi-brand SKUs across Arçelik, Beko, Bosch, Siemens, Profilo, Samsung, Vestel, Altus, etc. Capacity (liters/kg) and energy class are regex-extracted from titles. Records land in `arcelik_marketplace_prices` (id, marketplace, brand, title, category, price, capacityLiters/Kg, energyClass, productUrl, scrapeRunId, scrapedAt). After every scrape, `rebuildEquivalences()` in `artifacts/api-server/src/lib/matching.ts` runs a cross-brand matching algorithm: for each Arçelik product, it scores each non-Arçelik-family marketplace record on (a) category match, (b) capacity within 10–20%, (c) energy class within one tier, (d) price within 25–50%, (e) title-token Jaccard overlap. Matches with confidence ≥0.5 are kept (top 3 per competitor brand per product), persisted to `arcelik_product_equivalences` with `matchBasis` JSON capturing all reasons + numeric deltas. Each marketplace row also gets its single best `arcelikProductId` link written back. New API routes: `GET /api/arcelik/marketplace-prices` (filter by brand/category/marketplace/arcelikProductId), `GET /api/arcelik/marketplace-prices/summary` (aggregated min/avg/max/count grouped by marketplace+brand+category, last 14 days), `GET /api/arcelik/equivalences` (filter by arcelikProductId/brand/minConfidence). Manual scrape via `POST /api/arcelik/scrape` now reports `n11` and `equivalences` in `scrapedCounts`.
