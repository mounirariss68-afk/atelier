# Maven AI — Marketing Website + Diagnostic Suite

## Overview
This project delivers a marketing website for Maven AI, an AI advisory and engineering firm, built as a React + Vite single-page application. Its core purpose is to showcase Maven AI's expertise, services, and diagnostic capabilities, with a focus on a premium user experience. A key component is the integrated Maven AI Diagnostic Assessment Suite, offering four free, bilingual (EN/AR) diagnostic wizards (ARI, MVI, DAFI, UVR). This suite is backed by an Express API and a Postgres database, generating AI-powered executive memos and branded PDF reports.

## System Architecture
The project utilizes a modern web stack: React, Vite, TypeScript, Tailwind CSS v4, Framer Motion for animations, and Wouter for routing, all managed within a pnpm monorepo. The design adheres to a premium aesthetic, using a consistent brand identity with a navy, teal, and amber color scheme, and Plus Jakarta Sans typography.

**Key Features:**
-   **UI/UX:** Responsive design with mobile-first considerations, animated sections, and a floating amber FAB for the chat widget.
-   **Content Management:** Static content (founders, services, insights, industries) is centrally managed within `src/data/content.ts` and `lib/maven-content`.
-   **Navigation & Routing:** Comprehensive routing supports main pages, service details, articles, industry profiles, a dynamic marketplace for demo tools, and dedicated routes for diagnostic assessments and multi-variant demos.
-   **Marketplace:** Features a filterable catalog of demo tools with detailed pages, including multi-demo variants like the Arçelik Pricing Intelligence demo. This demo incorporates complex UIs (KPI summaries, heatmaps, radar charts, campaign builders, pricing simulators, Gantt calendars) with AI chat integrations and bilingual intent patterns, along with an agentic pricing intelligence layer.
-   **Arçelik Demo Data Architecture:** Pricing data is stored in PostgreSQL (15 Drizzle schema tables) with provenance metadata. Data is seeded from a baseline JSON and supplemented by web scrapers. An automated scheduler updates prices daily, tracking history and logging scrape runs.
-   **Cross-Brand Marketplace Intelligence:** A live N11 + Trendyol + Hepsiburada marketplace pipeline ingests competitor SKUs (`arcelik_marketplace_prices`), extracts structured PDP specs (`arcelik_product_specs` — capacity, energy class, dimensions, RPM, noise), and builds confidence-scored cross-brand equivalences (`arcelik_product_equivalences`) via a multi-signal matcher (category, capacity, energy tier, price band, title token overlap, subtype synonyms). An append-only `arcelik_marketplace_price_history` captures per-source price movements. API exposes `/api/arcelik/{coverage, marketplace-prices, marketplace-prices/summary, marketplace-prices/history, equivalences, product-specs}`.
-   **Arçelik Demo i18n:** Full TR/EN internationalization for the demo, including UI elements, chat intents, and seeded data, ensuring a fully bilingual user experience.
-   **Diagnostic Suite:** A shared TypeScript library powers the scoring engine, i18n, and framework definitions. The UI includes a wizard engine, results screens with data visualizations, and React-PDF for branded reports supporting English and Arabic (with RTL toggle).
-   **AI Chat Assistant:** A site-wide assistant integrates with server-side (Anthropic/OpenAI) and client-side logic, leveraging a shared knowledge base, an OpenAPI-defined `POST /chat` endpoint for SSE, strict allow-listing for internal links, and features rate limiting, streaming responses, and session persistence.
-   **New Dashboard Views (Arçelik Demo):** Includes a **Product Comparison View** (cards, scatter plot, search/sort) and a **Market Whitespace View** (bubble chart, bar chart, opportunity cards), both with full TR/EN i18n. A specialized AI Agents Panel within the `AgentDecisionsView` shows 9 agents with real-time status and metrics.
-   **Network Ops War Room — NOC Director Console:** A second variant of the `network-ops-war-room` demo at `/demo/network-ops-war-room/noc`, modelled as Reem Al-Dosari's daily console at Sahara Telecom. Six nav views (Live map, Incident workspace, Approvals, Service health, Field ops, Audit log) over a stylised GCC SVG topology (~30 sites, 50 links, 6 incidents, 4 enterprise SLAs, 8 field crews) with EN/AR + RTL via `document.documentElement.dir`, an AI chat panel with 8 intents and three agent personas (analyst / topology / mitigation). Lives under `src/components/demo/network-ops/` (shell `NocConsole.tsx`, views in `views/`, `GccMap.tsx`, `AiChat.tsx`, `chatIntents.ts`, `noc-i18n.ts`, scoped `DemoLangContext`). Seed data in `src/data/network-ops-seed.ts`. Three registration points: `lib/maven-content/src/knowledge.ts` (`demoVariants` array on the Network Ops tool — `cockpit` + `noc`), `pages/Demo.tsx` (early-return for `slug === "network-ops-war-room" && variant === "noc"`, plus `cockpit` variant fallback to the bare scenario), and the marketplace launch buttons (auto-rendered from `demoVariants`).

## Building an Atelier agent
The Atelier (`artifacts/atelier`) follows a single canonical contract for every agent — Drafter, Sentinel, Analyst, or Rule-based. The full specification lives in **`artifacts/atelier/AGENT_STANDARD.md`**; do not write or change Atelier agent code without reading it first. In summary:

-   **One source of truth** for every agent: an entry in `lib/agents/src/registry.ts` (`defineAgent({...})`) declares the input + output Zod schemas, model, tools, guardrails, human checkpoints, and evals. The registry is the contract between the prompt, the runner, the route, the UI, and the fixtures.
-   **Locked file layout:** prompt at `artifacts/api-server/prompts/<agent_id>/v<n>.md`, runner hook in `artifacts/api-server/src/lib/atelier-agents/runner.ts`, route in `artifacts/api-server/src/routes/atelier/agentRoutes.ts`, fixture at `artifacts/api-server/tests/agents/<agent_id>/golden.json`. UI is registry-driven via `artifacts/atelier/src/pages/{Agents,AgentProfile,AgentRun}.tsx` — bespoke views are opt-in only.
-   **Shared lifecycle helper:** new agents should call `runAgent({...}, async ctx => {...})` from `artifacts/api-server/src/lib/atelier-agents/runAgent.ts`, which guarantees Zod input/output validation, daily budget enforcement, `agent.start` / `agent.complete` audit events, and mock-fallback flagging. The original 15 hand-rolled `run<X>` functions in `runner.ts` predate the helper but conform to the same lifecycle (they call the same `startRun` / `progressRun` / `completeRun` / `failRun` primitives directly).
-   **Definition of Done:** registry entry + prompt + runner + route + fixture + at least one eval + correct status flag (`mvp` / `registered` / `stub`). Run `pnpm --filter @workspace/api-server test:agents` to validate every fixture against the registry's Zod schemas.
-   **Reconciled post-MVP agents:** Burn Sentinel, Utilization Analyst, Expense Auditor, Pricing Strategist, Win/Loss Interviewer (status `mvp`) and Case Study Picker, Theme Curator (status `registered`) now have full registry entries and golden fixtures alongside the 8 starred MVP agents.

## External Dependencies
-   **AI Integrations:** Anthropic (claude-sonnet-4-5) and OpenAI (gpt-5) for AI memo generation and chat assistant responses.
-   **Email Service:** Resend for sending emails.
-   **Database:** PostgreSQL for persistent storage of assessment submissions, call requests, team invitations, and Arçelik demo pricing data (15 tables, including marketplace prices, structured PDP specs, cross-brand equivalences, and marketplace price history).
-   **Scraper Dependencies:** `playwright-core` (headless Chromium) drives twelve brand-site scrapers plus the N11, Trendyol, and Hepsiburada marketplace pipelines (Hepsiburada uses /ara?q={query}&sayfa={n} search-style pagination with aggressive scroll-to-mount lazy-load and the same per-category title-keyword gate as Trendyol; Teknosa remains blocked by Akamai 403). Working brand scrapers (9): Arçelik, Beko, Vestel, Bosch, Samsung, LG, Profilo, Grundig, **Siemens**. Honest stub scrapers (3) returning `[]` with logged reasons: Electrolux + AEG (electrolux.com.tr, aeg.com.tr — marketing-only sites with no online catalog), Regal (regal.com.tr — site times out >25s from this network). Siemens uses `siemens-home.bsh-group.com/tr` with the same BSH "click-more" pagination as Bosch (12 product-teasers per page across 10 BSH category paths covering refrigeration, washing, dishwashers, cooking — yields ~70–100 SKUs). Each brand walks ~9–18 categories with site-appropriate pagination (Hybris static lists for Arçelik/Beko/Grundig, scroll-to-bottom lazy-load for Vestel and LG, "Daha fazla görüntüle" click-loops for Bosch/Profilo/Siemens, JSON-LD + DOM-card hybrid for Samsung). LG covers refrigerators/washers/dishwashers/klima/TVs across 16 category URLs but has no oven/cooking catalog on lg.com/tr (returns 404). LG card pricing must use the `.cell-price` selector specifically — the parent `.neo-price--price` glues the discount badge + sale price + strikethrough into one corrupt text node. Match logic prefers brand-specific maps then falls back: Siemens→siemensMap→boschMap→profiloMap; Regal→regalMap→vestelMap; Electrolux/AEG→aegMap→electroluxMap→marketplace pipeline. Brand scrapers run in pairs (concurrency=2) to fit a <30-min cron budget (now ~25 min including spec extraction).
