---
name: Chat two-phase confirm is model-trusted; commit-token defense
description: Why finance-doc chat writes HMAC-stamp their pending input, and when new capabilities should do the same
---

The orchestrator's tool loop executes ANY tool call whose input carries `confirm:true` — including one the model fabricates in the first turn. `twoPhaseConfirm: true` is declarative; the real gate is that the model normally returns the confirmation envelope instead of committing. `/confirm` replays the server-persisted `pendingWrite.input` verbatim; the `needs_confirmation` frame only shows summary+diff, never `pending.input`.

**Defense pattern** (see `finance-doc-capabilities.ts`): phase 1 stamps `commitToken = HMAC(SESSION_SECRET, tool + canonicalized input minus confirm/commitToken)` into `pending.input`; phase 2 commits only when the token verifies, otherwise it degrades to the phase-1 preview (never errors, never writes). The model can't compute the token, and `/confirm` replays it untouched.

**Why:** injected instructions in attached documents can steer the model to emit `confirm:true` directly; for founder-sensitive writes (bank accounts, payables) the preview card must be unforgeable.

**How to apply:** the orchestrator now has a GLOBAL guard (2026-08-14): the tool-dispatch loop in `atelier-cli/index.ts` strips model-originated `confirm:true` (and `commitToken`) on every twoPhaseConfirm capability (non-catalog legacy writes default to two-phase), so a forged commit degrades to the phase-1 preview. Commits happen only via `/confirm`'s replay of the server-persisted pendingWrite — that path, clarification/disambiguation continuations, and the async runner call `tool.run` directly and are untouched by that loop guard. The clarification/disambiguation continuations now have their OWN strip (2026-08-14): `stripContinuationApproval()` in `atelier-cli/index.ts` removes `confirm`/`commitToken` from the merged continuation input (server partial + client answer values) right before `tool.run` for twoPhaseConfirm writes — regression: `test:clarify-smuggle` (in `test:chat-suite`). The finance HMAC token remains as defense-in-depth for direct tool.run callers. Regression: `test:confirm-forgery` (also appended to `test:chat-suite`). New commit paths must not execute model-supplied confirm flags.
## Async hand-off removed (2026-08-14)
The background async hand-off (long write plans / `async:true` on POST /cli/turn) used to replay an UNAPPROVED pendingWrite via `tool.run()` directly — bypassing the confirm card, typed-name gate, and approver-role separation. It is removed: a turn ending `awaiting_confirmation` always stays awaiting_confirmation; writes commit ONLY via `confirmPendingWrite`. `RunTurnInput.async` is kept but inert; `async_dispatched` status/frames survive only for historical rows and client compat. Never reintroduce a background commit path without routing it through the /confirm gates. Probe: tests/cli-turn/async-approval-gate.ts (in test:chat-suite).
