---
name: api-client-react barrel is hand-maintained
description: New orval-generated hooks/types do not auto-export; you must hand-add hook names to the barrel index.
---

`@workspace/api-client-react` resolves `"."` to `src/index.ts` (source, no dist build). That barrel is an EXPLICIT named-export list and is **NOT** regenerated by orval.

When you add an endpoint to `lib/api-spec/openapi.yaml` and run `pnpm --filter @workspace/api-spec run codegen`, orval rewrites `lib/api-client-react/src/generated/api.ts` (hooks) and `generated/api.schemas.ts` (types) — but the barrel is untouched.

**Symptom:** consumers (e.g. atelier) fail tsc with "no exported member useAtelierX / getAtelierXQueryKey" even though the symbol clearly exists in `generated/api.ts`.

**Fix:** hand-add the new names to the `export { ... } from "./generated/api"` block in `index.ts`, mirroring an existing entry. For a query endpoint add `getXUrl, getXQueryKey, getXQueryOptions, useX`; for a mutation add `getXUrl, getXMutationOptions, useX`.

**Why types don't need this:** schema types flow through `export * from "./generated/api.schemas"` (wildcard), so new request/response types are exported automatically — only the hooks/query-key helpers need manual barrel entries.
