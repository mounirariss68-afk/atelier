Project: AICo Employee Portal — "The Atelier"
You are the lead engineer building the internal operating system for a senior-led, agentic-native AI consulting firm. The portal is where every employee — Partner, Principal, Engagement Lead, Engineer, Designer — runs the full project lifecycle, with named AI agents preparing work at each step. Humans always decide; agents prepare, draft, research, review.
The portal is the logged-in companion to the public AICo / Maven AI website. Visitors clicking "Sign in" on the public site land here.
Build the shell + MVP modules described below. The shell must be production-quality. The MVP modules must be demo-quality and end-to-end clickable with realistic seeded data; the deeper agent runtime is real (Claude API), not faked.

0. Non-negotiable principles (apply to every screen)

Senior-led, not seat-filled. Every workspace shows the named Partner and Engagement Lead on the engagement. The portal does not optimize for utilization graphs; it optimizes for partner judgment leverage. No "available bench" view in MVP.
Agents prepare; humans commit. Every agent action ends in a human "Approve / Edit / Reject" panel with a named decider, timestamp, rationale, and an audit entry. No silent autonomous writes to client folders or external systems.
Show the work. Every agent run renders a live "Agent activity" stream — sub-agent name, what it's reading, citations pulled, confidence chip, what it's blocked on. The stream is collapsible but never hidden.
Source-grounded by construction. Agents cite sources for every claim. If a citation is missing, the UI renders a red "unsourced claim" pill and the human must either accept the risk (logged) or send it back. No silent fabrication.
Reusable IP compounds. Every artifact produced (POV, proposal section, deliverable, prompt) is tagged for reuse and pushed into the Knowledge Atelier. Reuse is one click, with provenance.
Bilingual-aware. EN is default. The portal does not auto-translate Arabic client documents; instead, when a non-English source is detected, the system labels it and surfaces a "Translate with citation" flow that preserves the original in the audit log.
Audit trail is a first-class object. Every entity (Opportunity, Engagement, Deliverable, Agent Run) has an immutable audit feed that looks like a system of record, not a debug log. The audit is exportable to PDF for governance/insurance reasons.
Confidentiality is the default. Client data is isolated per engagement. The cross-engagement Knowledge Atelier only ingests artifacts that the engagement Partner has explicitly marked "share to firm" — never silent.

3. Personas the portal must serve
The portal must work for these five named personas. Build a persona switcher in the top-right that swaps the seeded data (real auth applies in prod):

The Partner (e.g., Mounir / Gökhan) — owns origination, client relationships, partner-level judgment, go/no-go calls, deliverable sign-off, pricing decisions. Spends 20% in the portal; needs zero-click dashboards and one-click approvals.
The Engagement Lead (Principal) — runs the engagement day-to-day. Drives the work plan, manages the agent fleet, edits deliverables, owns client comms. Lives in the portal 60% of the day.
The Subject Matter Lead — pulled in for specific expertise (data architecture, agent design, change management). Drops in/out of multiple engagements; needs fast context loading.
The AI Engineer — builds custom agents and prototypes for client work. Uses the portal to scaffold projects, push prompts into the Atelier, and run evals.
The Business Developer / Pursuit Lead — owns the pipeline, qualifies opportunities, drives proposal production. Lives in /pipeline.

Each persona has a tailored Atelier Home (see §5).

4. The PLM model the portal enforces
The firm runs a 6-stage Project Lifecycle (PLM) with explicit gates. Every opportunity and engagement carries a plm_stage field. The UI surfaces the current stage as a gold-pill badge with a tooltip showing the gate criteria.

A "Qualify" decision (5Cs — Client, Competition, Capability, Capacity, Contract) must be logged at the Shape→Pursue gate. The system blocks advance until the Partner records a Qualify verdict and rationale.
The PLM is intentionally hybrid: stage-gated enough for governance and pipeline hygiene, but lean enough that a single Partner + Principal can run an opportunity from Identify to Mobilize in days, not months. This matches AICo's "three-day scope, three-week prototype, 90-day MVP" promise.

6.2 Tabs and what each does
/brief — A one-page brief that is auto-drafted by the Pursuit Scout agent (see §8) the moment an opportunity is created. The brief includes: client snapshot, decision-maker map (with LinkedIn/Wikipedia citations), known initiatives, AICo's hypothesis on the angle, comparable engagements from the Atelier, risks, recommended next move. Human edits with track-changes; agent re-runs on demand.
/research — A structured dossier with citation-bound facts. Each fact is a row: claim | source | retrieved_at | confidence | included_in_brief? | included_in_pov?. Sources are clickable. Facts can be promoted into the brief, the POV, or the proposal — promotion carries the citation.
/pov — POV Studio (see §8 — the POV Author agent). Drafts a 6–10 page point-of-view document in either HTML (Tasama-style, the live web POV pattern) or DOCX. The HTML POV uses the same brand system; DOCX uses the AICo report template. Versioned. Side-by-side diff between versions.
/proposal — Proposal Studio. Section-by-section drafting, each section owned by a sub-agent (Context, Approach, Workplan, Team, Pricing, Case Studies, Terms). Sections marked GREEN/AMBER/RED for completeness. Composer assembles the final DOCX/PDF.
/meetings — Meeting log. Each meeting row: title, date, attendees, transcript (uploaded or captured via the Meeting Scribe), summary, decisions, action items, requirements identified, follow-ups owed. The Meeting Scribe agent processes uploaded transcripts/audio and produces all of the above; the human approves before any of it is written to the engagement record.
/artifacts — File attachments. Box / Replit Object Storage connector. Drag-and-drop. Each artifact gets an AI-generated 40-word abstract (Atelier Curator) and is tagged.
/audit — Append-only event log: every agent run, every human action, every status change.

A gold-bordered toolbar at the top of the opportunity workspace surfaces five primary actions, each backed by an agent:

/charter — Engagement charter. Drafted by the Charter Architect agent from the won proposal + kickoff transcript. Lays out: objectives, scope, out-of-scope, governance, success metrics, value hypothesis. The Charter Architect proposes a hypothesis tree (MECE issue decomposition) that becomes the spine of the work plan.

/processes — Process discovery + agent design canvas (see §8 — the Agent Architect). Lets the team draw the current process (BPMN-lite), mark agentifiable steps, and auto-generate high-level agent designs.
/meetings — Client meeting log, same as opportunity meetings.
/artifacts — Files.
/audit — Immutable feed.

7.3 Quality gates inside delivery
Two automated gate reviews trigger on the deliverable workspace:

Hypothesis check — Before a deliverable is sent to the client, the Synthesis Critic agent reads it against the engagement hypothesis tree and flags claims that lack evidence, sections that drift off-hypothesis, and pyramid-principle violations (governing thought missing, MECE breaks).
Partner review — A Partner must explicitly approve every external client deliverable. The system blocks "Send to client" until a named Partner has clicked Approve with a 1-line rationale. This is the human counterpart to HAPA — call it the Partner Authority Lock.


8. The agent runtime (the heart of the portal)
8.1 Architecture
A single typed agent framework. Every named agent is a registered class in /lib/agents/ with this shape:
tsinterface Agent {
  id: string;                           // e.g., 'pursuit_scout'
  name: string;                         // 'Pursuit Scout'
  purpose: string;                      // one-line
  inputs: AgentInputSchema;             // Zod schema
  outputs: AgentOutputSchema;           // Zod schema
  tools: ToolRef[];                     // ['web_search','box.read','knowledge.search', ...]
  systemPrompt: string;                 // versioned in /prompts/
  model: 'claude-sonnet-4-6' | 'claude-haiku-4-5' | 'claude-opus-4-6';
  guardrails: GuardrailRef[];           // ['must_cite_sources','no_pii_to_third_party', ...]
  humanCheckpoints: CheckpointSpec[];   // where the human MUST approve before continuing
  evals: EvalRef[];                     // tests in /evals/agents/[id]/
}
Agent runs are first-class objects (AgentRun) with: agent_id, triggered_by_user_id, engagement_id or opportunity_id, inputs, tool_calls[], intermediate_steps[], output, human_decisions[], status, cost_usd, duration_ms.
The Agent Activity Stream (persistent right rail) is a live view of the user's active AgentRuns. Each step renders as a card with: sub-agent name, tool call, evidence/citations pulled, confidence chip (GREEN/AMBER/RED), status. Clicking a step opens the evidence drawer (full source + retrieved text + retrieved time).

8.4 Detailed specs — the MVP 8
Each agent below ships with: a Zod input schema, a Zod output schema, a versioned system prompt in /prompts/[agent_id]/v1.md, a guardrail set, defined human checkpoints, and at least 5 evals.
8.4.1 Pursuit Scout

Purpose: Produce a 1-page opportunity brief for a named account + buyer that a Partner could read in 90 seconds and decide whether to pursue.
Inputs: { account_name, buyer_name?, buyer_role?, hypothesized_offering, depth: 'quick'|'deep' }
Output: { executive_summary, decision_maker_map[], recent_initiatives[], comparable_aico_work[], hypothesis, risks[], recommended_next_move, sources[] } — all claims tied to a sources[].id.
Tools: web_search, web_fetch, knowledge.search, linkedin.lookup (stub).
Model: Sonnet 4.6 for deep, Haiku 4.5 for quick.
Guardrails: Every claim must cite at least one source; if a source is older than 18 months it is flagged AMBER; PII about decision-makers limited to public role + recent public statements.
Human checkpoints: Brief is rendered as a draft; Partner clicks Approve before brief becomes the opportunity's official brief.
Evals: seed accounts (Tasama, Dubai Municipality, STC) with golden briefs; eval scores citation precision, hallucination rate, and Partner-acceptance rate.

8.4.2 POV Author

Purpose: Draft a client-ready POV (the Tasama/Dogan-style HTML one-pager, or a DOCX equivalent) for a named buyer that articulates AICo's view on the buyer's problem and the move AICo recommends.
Inputs: { opportunity_id, audience: { name, role, org }, format: 'html'|'docx', length_pages: 4|6|8|10, must_include_themes[], must_cite_sources[], banned_topics[], deadline }
Output: { rendered_file_url, outline, sections[], citations[], reusable_blocks_suggested[] }. The HTML output uses the same brand system as the public site and the Tasama POV; the DOCX uses the AICo report template.
Tools: knowledge.search (pull comparable POVs), web_search (current evidence), html.generate, docx.generate.
Model: Sonnet 4.6 draft → Opus 4.6 polish pass on demand (toggle in the prompt sheet).
Sub-agents (chained): Outline Designer → Section Writers (one per section, parallel) → Citation Binder → Brand Stylist → Synthesis Critic (pre-release review).
Guardrails: Pyramid-principle structure (governing thought up top); every section closes with a 1-line "so what"; no claim without a citation; client-name handling rules (don't promise what's not in the proposal).
Human checkpoints: (1) Approve outline before writing; (2) Approve final draft before "Save as official POV." Human edits are tracked.
Evals: golden POV set (Tasama, Dogan, DGE Effortless), measure brand-compliance score, citation-coverage %, partner-acceptance rate, time-to-first-readable-draft.

8.4.3 Proposal Composer

Purpose: From a defined opportunity + RFP (if any), produce a client-ready proposal DOCX/PDF with the AICo proposal sections.
Inputs: { opportunity_id, rfp_file_id?, sections_required[], team_proposed[], pricing_intent, deadline }
Output: { proposal_file_url, sections[]: { id, name, owner_agent, status, content, citations }, pricing_model, win_themes[], compliance_matrix }
Sub-agents: Context Writer, Approach Writer, Workplan Writer, Team & Bios Writer, Case Study Picker, Pricing Analyst, Terms & Risk Writer, Compliance Reviewer.
Tools: knowledge.search, web_search, file.read (RFP), docx.generate, pdf.generate.
Model: Sonnet 4.6 throughout; Opus 4.6 for the Approach section on demand.
Guardrails: Every promise made in the proposal must map to a deliverable in the workplan; pricing must hit the configured target margin or trigger a Partner override; compliance matrix must be 100% green or rendered red.
Human checkpoints: (1) Section assignments confirmed; (2) Pricing approved by Partner; (3) Final read by Partner; (4) Explicit "Send to client" click on the submission action.
Evals: golden proposals (Tasama BPO, DGE Effortless), measure compliance-matrix accuracy, win-theme coverage, partner-acceptance rate.

8.4.4 Meeting Scribe

Purpose: Turn a client meeting (uploaded audio/video, or a paste-in transcript, or a live bot recording — last option v2) into structured engagement memory.
Inputs: { source: { type: 'upload'|'paste'|'live_bot', file_id?, text?, meeting_id? }, meeting_metadata: { title, attendees, date, opportunity_or_engagement_id }, scribe_mode: 'discovery'|'workshop'|'steering'|'kickoff' }
Output: { transcript_clean, summary, decisions[], action_items[]: { owner, due, description }, requirements_captured[], risks_raised[], topics_to_research[], suggested_followups[], suggested_prototype_brief? }
Sub-agents: Transcript Cleaner, Summarizer, Decision Extractor, Requirement Extractor, Risk Extractor, Follow-up Composer, Prototype Brief Drafter (only fires in discovery mode when a viable prototype is implied).
Tools: transcribe.audio, knowledge.search (look up adjacent prior context), web_search (best-practice references for the topics raised), replit.scaffold (only when prototype brief is generated — drafts a Replit prompt, does NOT send it).
Model: Haiku 4.5 for transcript clean + extraction; Sonnet 4.6 for synthesis and prototype brief.
Guardrails: Speaker attribution must be preserved or marked "unclear"; client-confidential terms detected via a configurable redaction list are flagged before any cross-engagement write; auto-research is scoped to the meeting's topics only.
Human checkpoints: (1) Summary + action items reviewed before they are pushed to the engagement record; (2) Prototype brief, if generated, is presented as a draft for explicit "Generate prototype" action.
Evals: seeded meetings (Tasama discovery, Aldrees BOQ workshop), measure action-item recall, decision recall, no-hallucination rate.

8.4.5 Charter Architect

Purpose: Within 24h of engagement signature, draft the engagement charter and a hypothesis tree.
Inputs: { engagement_id, won_proposal_file_id, kickoff_transcript_id? }
Output: { charter: { objectives, scope, out_of_scope, success_metrics, governance, value_hypothesis }, hypothesis_tree: { rootIssue, branches[]: { hypothesis, sub_hypotheses[], evidence_required[] } }, raid_baseline[], proposed_workstreams[] }
Sub-agents: Objective Distiller, Scope Boundarist, Hypothesis Tree Builder (MECE check), RAID Baseliner.
Tools: knowledge.search (comparable charters), file.read.
Model: Sonnet 4.6; Opus 4.6 for the hypothesis tree polish on demand.
Guardrails: Every objective must be paired with a measurable success metric; scope and out-of-scope must be MECE; hypothesis tree limited to 3 levels deep by default (configurable).
Human checkpoints: Engagement Lead reviews; Partner signs off before charter goes to the client.
Evals: golden charters; measure MECE-violations-flagged, objective↔metric pairing rate, partner-acceptance rate.

8.4.6 Agent Architect

Purpose: From a captured process (text description, meeting transcript, uploaded BPMN, or hand-drawn flowchart photo), produce: (a) a clean process diagram, (b) an "agentifiable" annotation per step, (c) a set of candidate agent designs with their tools, guardrails, and human checkpoints.
Inputs: { source: text|file|image|transcript, scope_hint, depth: 'sketch'|'design' }
Output: { process_diagram_mermaid, steps[]: { id, name, current_owner, agentifiable: 'yes'|'partial'|'no', rationale, candidate_agent_id? }, candidate_agents[]: { id, name, purpose, inputs, outputs, tools, guardrails, human_checkpoints } }
Sub-agents: Process Reader, Step Classifier, Agentifiability Judge, Agent Designer.
Tools: bpmn.render (Mermaid in MVP), knowledge.search (pull comparable agent designs from the Atelier).
Model: Sonnet 4.6.
Guardrails: Agentifiability classification must include rationale; no candidate agent without a human checkpoint defined; high-risk agents (financial commitment, customer communication, irreversible action) flagged for Partner attention.
Human checkpoints: Partner / Engagement Lead reviews each candidate agent design before it is added to the engagement's agent runtime.
Evals: seeded processes (Aldrees BOQ, Tasama shared services intake, DGE service catalog), measure agentifiability classification accuracy, agent-design completeness, partner-acceptance.

8.4.7 Prototype Forge

Purpose: When a discovery / workshop produces a viable prototype idea, generate a Replit-ready build prompt (the same pattern as the DGE Effortless prompt) and optionally scaffold the repo.
Inputs: { engagement_or_opportunity_id, prototype_brief: { name, audience, problem, agentic_thesis, demos[], constraints, brand_overrides? }, deliverable_target_date }
Output: { replit_prompt_md, repo_scaffold_url?, build_plan, demo_storyboard }
Sub-agents: Architecture Drafter, Demo Storyboarder, Brand Translator (inherits the AICo brand by default; can override), Prompt Composer.
Tools: knowledge.search (pull prior prototype prompts), replit.scaffold (stub in MVP — generates the markdown only).
Model: Sonnet 4.6 → Opus 4.6 polish.
Guardrails: Generated prompts must include the AICo non-negotiables block (human authority sovereign; show the work; audit trail; bilingual-aware; watermark synthetic data). No real client data referenced in the generated prompt unless the engagement Partner has approved.
Human checkpoints: Engagement Lead approves the brief before generation; Partner approves the generated prompt before it goes to Replit.
Evals: golden prompts (DGE Effortless, Tasama BPO concept), measure structural completeness, brand-compliance, no-leak rate.

8.4.8 Synthesis Critic

Purpose: Quality-gate every external deliverable before client release. The agentic equivalent of a peer / partner review pass.
Inputs: { deliverable_id, hypothesis_tree_id?, audience }
Output: { issues[]: { type, severity, location, suggestion }, pyramid_score, evidence_coverage_pct, off_hypothesis_sections[], readiness: 'green'|'amber'|'red' }
Tools: knowledge.search (comparable past readouts), file.read.
Model: Opus 4.6 (high-stakes, low-volume).
Guardrails: Critic does not edit; it only flags. Edits require a human or an explicit re-run of the originating writer agent.
Human checkpoints: Engagement Lead reviews the issues; "Send to client" is blocked until readiness is GREEN or a Partner has logged an override rationale.
Evals: golden deliverables with seeded defects; measure precision/recall of issue detection, pyramid-score correlation with partner judgment.

8.5 Prompt library structure
Every agent's system prompt lives at /prompts/[agent_id]/v[n].md. Each prompt has YAML front matter: agent_id, version, author, created, model, eval_set_id, status (draft|active|deprecated). Activating a new version requires the eval suite to pass at or above the current active version's score.
A prompt_library table indexes everything and is the source for the /atelier/prompts UI. Every prompt is annotated with: when it should fire, what it produces, who owns it. A "Prompt Librarian" agent watches for prompt patterns repeating across engagements and proposes new library entries.

9.3 Acceptance criteria for MVP (must all be true to ship v1)
A reviewer should be able to:

Sign in and land on the Atelier Home, see a Pane A populated with at least 3 prioritized items.
Create a new opportunity from a single field ("client name + 1-line context") and watch the Pursuit Scout populate the brief within 60s, with citations.
From an opportunity, click "Draft a POV", complete the structured prompt sheet, and receive a brand-correct HTML POV draft with at least 4 sections, each citation-bound, in under 5 minutes wall-clock.
Upload a 30-minute meeting recording to an engagement, watch the Meeting Scribe produce a transcript + decisions + action items + 3 captured requirements; click Approve and see the action items land on the engagement workplan skeleton.
From the engagement, open the /processes tab, paste a process description, and receive a Mermaid process diagram with agentifiability annotations on each step + at least 3 candidate agent designs.
From an engagement deliverable, click "Send to client" and be blocked until a named Partner clicks Approve, with the Synthesis Critic having pre-flagged at least one issue.
From the Atelier, search "Tasama" and find the seeded POV + a Charter, with provenance.
Every action above produced a row in the entity's /audit tab.

9.4 Non-functional requirements

Performance: First meaningful paint < 1.5s; agent first token < 4s for Haiku-backed agents, < 8s for Sonnet, < 15s for Opus; long-running agent runs stream incrementally and are resumable.
Auth: Replit Auth or Clerk; OAuth (Google + Microsoft) ready; per-user MFA; per-role permissions (Partner / Lead / SME / Engineer / BD).
Tenancy: All tables carry org_id; row-level security enforced in Postgres so the codebase is ready to host a future "Client Portal" tenant.
Confidentiality: Engagement data is partitioned. Cross-engagement reads require an Atelier promotion record. The audit log records every cross-engagement read.
Cost controls: Per-user per-day token budget; per-agent token budget; admin can disable Opus. Cost is rendered on every agent run card.
Observability: Every agent run logged with model, tokens in/out, cost, duration, tool calls. Errors surface as user-facing cards with retry.
Compliance: Data residency configurable (Postgres region); PII-redaction pass before any cross-engagement write; export-to-PDF of the audit log for any entity.
Accessibility: WCAG 2.2 AA on the shell; keyboard-navigable agent activity stream; color contrast respected against the deep navy.

Multi-tenancy as a paying product (the codebase is ready; the billing/admin product is not in MVP).

11. Cross-cutting UX patterns

Prompt sheets, not chat boxes. Every agent action opens a structured form with the inputs the agent needs. A "raw prompt" advanced toggle is one click away but hidden by default.
Approve / Edit / Reject triad on every agent output, with the human's name and rationale captured.
Citation-first surfaces. Any claim a user can act on shows a citation badge. Clicking opens the evidence drawer.
Diff-by-default. Every deliverable version is rendered as a diff against the prior version.
Provenance pills on Atelier assets — "Used in Tasama 2026" etc. — never anonymous reuse.
One-click "Pull into current workspace" on every Atelier asset.
Agent activity stream is the same component everywhere — collapse, but never disappear.

18. One-paragraph north star (paste into the agent's first system prompt)

AICo is a senior-led, agentic-native AI advisory and engineering firm in the GCC. The Atelier is the portal where every Partner, Principal, and Engineer runs the full project lifecycle — from spotting an opportunity to harvesting reusable IP after delivery — with named AI agents preparing the work at every step.
