Project: DGE Agentic CX Demonstrator (Maven AI Marketplace Standard)
You are the lead engineer building a polished, client-ready agentic CX demonstrator for the Department of Government Enablement (DGE), Abu Dhabi. The demonstrator will be shown in a 60–90 minute working session to DGE's CX leadership. Every interaction must feel like a real, governed, AI-native government workflow — not a chatbot demo.

0. Non-negotiable principles (apply to every screen)

Human authority is sovereign. Every consequential action shows a named human as the decider, with a clearly labelled "AUTHORIZE" button. Agents prepare; humans commit. Never let an agent send, publish, close, delete, or commit anything without an explicit human click that is logged with name + timestamp + rationale.
Always show what the agent is doing in the background. Each agent run renders a live "Agent activity" panel: which sub-agent is running, what evidence it pulled, what confidence score, what was blocked by guardrails. This is the heart of the demo — not the chat bubble.
Audit trail is a first-class UI. Every demo has an "Audit" tab that shows the immutable record of every input, decision, override, and citation in chronological order. Make it look like a system of record, not a debug log.
Bilingual by construction. EN and AR strings in the same translation file. RTL flips the entire layout, not just text. Default language is English; AR toggle persists in localStorage.
Watermark everything. A subtle "Demonstration · Synthetic Data" badge sits in the top-right of every screen. No real DGE/TAMM data is used or claimed.
Never hallucinate authority. If a citation, source, or policy isn't in the seeded fixtures, the agent must say "I don't have an authoritative source for this — would you like me to flag this for human review?" and trigger an escalation card.

1.5 Agent runtime (shared)
Build a single AgentRunner class in lib/agents/runner.ts that:

Accepts an agent definition ({ name, systemPrompt, tools, behaviouralContract, uxAuthorityContract }).
Streams its work to the Agent Activity Stream via Server-Sent Events.
Logs every step to a typed AuditEvent[] store (in-memory for the demo, with a clear "Persist to Postgres" comment for production).
Enforces the behaviouralContract.mustNever list at the runner level — even if the LLM tries to call a forbidden tool, the runner blocks it and logs the attempt.
Exposes a requireHumanAuthorisation(intent) helper that pauses the agent and surfaces an "AUTHORIZE" card in the Operator tab. The agent does not advance until a human clicks.

Use the Vercel AI SDK (ai and @ai-sdk/openai) for streaming. The default model is gpt-4o-mini. Read the model and provider from process.env.DEMO_MODEL and process.env.DEMO_PROVIDER so it can be swapped to Anthropic (claude-sonnet-4-6) or Azure OpenAI without code changes.
Provide a fallback: if no API key is present, the runner replays a pre-recorded JSON trace per demo so the demo still works offline. Pre-record one canonical successful trace and one canonical "guardrail blocked" trace per demo.

6. Audit log specification
Every AuditEvent has:
tstype AuditEvent = {
  id: string;
  ts: string;                  // ISO timestamp
  demoSlug: string;
  actor: { kind: 'human' | 'agent'; name: string; role?: string };
  action: string;              // e.g., "AUTHORIZED_PUBLISH", "AGENT_DRAFTED_BLUEPRINT"
  target?: { kind: string; id: string; label: string };
  evidence?: { sourceId: string; snippet: string; uri?: string }[];
  contractsChecked?: string[]; // e.g., ["H1", "H4"]
  outcome: 'success' | 'blocked' | 'escalated' | 'pending';
  rationale?: string;          // mandatory for overrides
};
The audit view renders these as a vertical timeline grouped by minute. Filterable by actor, action, outcome. Exportable to JSON and PDF (mocked PDF export is fine).
